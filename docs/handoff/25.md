# Handoff #25 — GET /api/profile

## Estado
`/api/profile` responde `display_name`, `avatar`, `level`, `level_name`, `current_xp`, `next_level_xp` do aluno do token. Aluno inexistente: 403 `forbidden`; sem token: 401 `token_expired`.

## Decisões
- Caso de uso estático `Application/Profile/GetProfile` (sem pattern extra); nível, nome e limiar vêm de `LevelPolicy` (P13, proposta ainda não aceita).
- Projeção só dos campos necessários (`FullName`, `Avatar`, `Xp`): CPF, RG, endereço e responsável nunca são lidos.
- `IgnoreQueryFilters` justificado: o host usa `AnonymousCurrentUser`, que enxerga zero alunos pelo filtro de unidade; o escopo aqui é o `Id` do aluno do token. Quando a Identidade fornecer `ICurrentUser` real para a API, reavaliar.
- `display_name` = `FullName` (a entidade não tem apelido; contrato congelado).
- Teste de integração liga `JsonUtilityContract` (UnitTests) por link de arquivo, sem pacote novo.
