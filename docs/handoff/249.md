## Como o adaptador funciona

1. `QuestionPromptBuilder.Build(request)` valida e monta o envelope (requisição inválida nem chega à rede).
2. **Uma** chamada a `POST https://api.anthropic.com/v1/messages`, pelo SDK: `model` = `Ai:Model` (não há nome de modelo no código), `max_tokens` = `1024 + 800 × quantidade`, `system` = prompt v1, um turno de usuário, `output_config` = `{ effort: "low", format: { type: "json_schema", schema } }`. O corpo não tem mais nada: sem `tools`, sem `temperature`/`top_p`/`top_k`, sem `stream`, sem `metadata` nem identificador de usuário (o teste confere a lista de propriedades).
3. O esquema é o do ADR-0004 §6.3: `{"questoes":[{enunciado,a,b,c,d,correta,explicacao}]}`, tudo obrigatório, `additionalProperties: false`, `correta` com `enum` `a`–`d`.
4. Resposta: `stop_reason = end_turn` → texto dos blocos de texto → `QuestionDraftOutputParser.Parse` (#246). O lote sai **sem filtro**; o validador (#236) é chamado pelo caso de uso, que tem o banco para a deduplicação.
5. `AiUsage`: `Provider = "Anthropic"`, `Model` = o que a resposta informou, `input_tokens`, `output_tokens`, duração medida e o `request-id` do cabeçalho.

| Situação | `QuestionDraftFailure` |
|---|---|
| `stop_reason = refusal` (HTTP 200, cobrado) | `Refused` |
| `stop_reason = max_tokens` ou qualquer outro; texto que não é o JSON esperado | `InvalidOutput` |
| 401, 403, 404; demais 4xx (400, 402, 413, 422) | `Misconfigured` |
| 429 | `RateLimited` |
| 429 com `error.details.error_code` de teto de gasto (`…spend_limit…`) | `ProviderUnavailable` |
| 5xx, 529, erro de conexão | `ProviderUnavailable` |
| prazo de `Ai:TimeoutSeconds` | `Timeout` |
| cancelamento por quem chamou | `OperationCanceledException` (não é convertido) |

- **Endereço e chave são passados na construção do cliente** (`BaseUrl` constante, `ApiKey` de `Ai:ApiKey`): `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY` e `ANTHROPIC_AUTH_TOKEN` não valem (há teste com as variáveis definidas). A chave vai só no cabeçalho `Authorization: Bearer`.
- **Uma tentativa por chamada**: `MaxRetries = 0` desliga a repetição do SDK. A repetição só de 429 e 5xx é a #251.
- **Log:** uma linha por geração (tokens, duração, `request-id`) ou por falha (motivo, `request-id`). Nunca chave, prompt, assunto, resposta nem a mensagem de erro do provedor.

## Decisões tomadas sem humano

- **Versão 13.10.0**, a que o ADR-0004 cita e o Henrique aprovou, e não a 13.12.0 publicada dois dias antes.
- **Dividir a Issue por comportamento** (o adaptador com os testes mediu 501 linhas): aqui uma tentativa por chamada; repetição na #251; registro na #250.
- **Saída estruturada por `output_config.format`, sem ferramenta** (ADR-0004 §6.3): o modelo não recebe ferramenta nenhuma.
- **`effort: low` com raciocínio adaptativo** (o padrão do modelo), ponto de partida do ADR; o ajuste fino depende de amostra com provedor real.
- **O adaptador usa o analisador, não o validador**: a porta devolve o lote sem filtro (ADR-0004 §4), e a deduplicação precisa do banco, que o adaptador não tem por desenho.
- **Demais 4xx viram `Misconfigured`**: inclusive o 400 de limite de gasto próprio do console, que o ADR mapeia para `ProviderUnavailable`. A documentação só o distingue pelo texto da mensagem, que o SDK manda não usar para decidir. Fica como pendência.
