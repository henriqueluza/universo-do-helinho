## Contrato que a UI vai consumir
```csharp
// Helinho.Application.Ai — registrado como Scoped em Composition/Areas/Ia.cs
public sealed class SuggestSingleDraft
{
    // Botão "Sugerir": síncrono, até WaitFor(Ai:TimeoutSeconds) = min(Ai:TimeoutSeconds, 20 s). Nunca salva questão nem sugestão.
    Task<SuggestSingleDraftResult> HandleAsync(QuizType quizType, AgeBand ageBand, CancellationToken ct);

    // Salvar a questão NOVA do criador. aiJobId vem do campo oculto; null ou inválido → a questão nasce Team.
    Task<(Guid QuestionId, QuestionOrigin Origin)> SaveAsync(
        Guid? aiJobId, QuizType quizType, AgeBand ageBand, string? statement, string? explanation,
        IReadOnlyList<string?> options, int? correctIndex, CancellationToken ct);

    static TimeSpan WaitFor(int timeoutSeconds); // o menor entre Ai:TimeoutSeconds e MaxWait (20 s)
}

public sealed record SuggestSingleDraftResult(
    SuggestSingleDraftStatus Status, Guid? JobId = null, QuestionDraft? Draft = null, string? FailureReason = null, AiQuotaExceeded? Quota = null);
public enum SuggestSingleDraftStatus { Suggested, Rejected, Failed, QuotaExceeded, Disabled, Forbidden }
```

- `Suggested`: `Draft` (enunciado, quatro alternativas, índice da correta, explicação) preenche o formulário; `JobId` vai no campo oculto. **O texto é gerado por IA: exibir só codificado.**
- `Rejected`: a IA respondeu, mas o validador descartou (inválida ou duplicada). Mensagem sugerida: a de `InvalidOutput`. O `JobId` devolvido não dá origem IA ao salvar (zero válidas).
- `Failed`: `FailureReason` é código de `AiFailureCodes` (`ai_timeout` → "A IA demorou para responder. O que você escreveu continua aqui.").
- `QuotaExceeded`: como no lote (cota por pessoa ou teto global). `Disabled` → 404 na borda.
- A regra "não sobrescreve o que a pessoa escreveu sem confirmação" (§15) é da tela: o caso de uso não recebe os campos do formulário.
- `SaveAsync` só serve para criar. Edição de questão existente continua em `SaveQuestion` (a origem nunca muda).

## Decisões tomadas sem humano
- **"Recente" = 2 horas** (`SuggestSingleDraft.JobValidity`). O ADR (§9.3) diz que o identificador só vale se o pedido for "recente", sem número; a Issue #261 fixa 2 horas. Duas horas cobrem quem deixa o formulário aberto e volta; é uma constante. Ver "Onde o ADR não bastou".
- **O pedido avulso é gravado antes da chamada**, já como `Processing`: conta na cota mesmo se a geração falhar ou a pessoa fechar a página. Se a requisição for cancelada no meio, o pedido é marcado `Failed` (`ai_timeout`) numa gravação que não usa o token cancelado.
- **Estado novo `Rejected`**, separado de `Failed`: a chamada deu certo e os tokens foram gastos (o pedido fica `Succeeded`, com `ValidCount = 0` e o motivo nos contadores), mas não há o que mostrar.
- **O prazo é um método puro, `SuggestSingleDraft.WaitFor`**, para o corte de 20 s ter teste sem esperar 20 segundos.
- **`SaveAsync` não confere se a IA está ligada**: a origem é um fato sobre o texto. Se a IA for desligada entre o "Sugerir" e o "Salvar", a questão ainda nasce com origem IA.
- **`SaveAsync` não confere o perfil para criar a questão**, como `SaveQuestion`: quem protege a criação é a política `Panel` da página. O perfil só decide a origem: sem Master ou Admin autenticado o identificador do pedido é ignorado e a questão nasce `Team` (teste).
- **Um pedido avulso pode dar origem IA a mais de uma questão** dentro das 2 horas (o ADR não pede uso único). Marcar IA a mais é o erro seguro; o contrário é que esconderia a origem.
- **Com o gerador fake, "Sugerir" repetido devolve a mesma sugestão** enquanto ela não for salva: o fake é determinístico e só pula enunciados que já existem. Não é defeito; vale avisar na demonstração.
- QA e documentação feitos nesta sessão, sem os subagentes `qa-tester` e `docs-writer`.

## Divergências do ADR-0004
- **Sem campo "Assunto" e sem resposta em JSON no "Sugerir" (§15 e o desenho `.ai-help` de `docs/design/recreio/preview/telas.html`, que traz "Assunto (opcional)"), decisão registrada:** o caso de uso pede "uma questão do tipo e da faixa escolhidos" e devolve um resultado tipado. Sem texto livre, não há o que sanear nem guardar; a resposta em JSON está fora do escopo da #261. Issue de continuação: #341.

## Onde o ADR não bastou
- O prazo de "recente" (acima).
- Se o identificador do pedido avulso deve valer uma vez só.
- O ADR pede prazo de "até 20 segundos" para o "Sugerir", mas o adaptador da Anthropic aplica por conta própria o prazo de `Ai:TimeoutSeconds` e repete 429 e 5xx dentro dele. Aqui o corte é o token de quem chama (20 s), que o adaptador respeita; uma repetição em andamento é interrompida e o resultado é `ai_timeout`.

## Segurança
- **Unbounded Consumption** (OWASP LLM 2025 LLM10 · skill da casa LLM06): cada "Sugerir" gasta 1 da cota por pessoa e do teto global (teste dos dois), inclusive quando falha; prazo de até 20 s.
- **Improper Output Handling** (LLM05 · LLM10): a sugestão passa pelo validador antes de voltar à tela; a inválida não é devolvida.
- **Excessive Agency** (LLM06 · LLM03): "Sugerir" não grava questão nem sugestão; quem salva é a pessoa.
- **Proveniência:** o identificador do campo oculto só vale para pedido avulso do mesmo usuário, concluído com sugestão válida e recente. Não dá para marcar origem com o pedido de outra pessoa, com um pedido em lote nem com um pedido rejeitado pelo validador. Valor forjado só consegue o que já é o padrão (origem da equipe).
- Nenhum dado de aluno, administrador ou unidade vai ao gerador (teste); nada vai para log.
