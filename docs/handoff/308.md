# Handoff #308 — `CaixaDeSaidaForaDeDevTests` aplica o `migrate` antes de pedir a página

## Estado
PR aberto com base na branch padrão. Só teste: um arquivo, 4 linhas.

## Causa
Os PRs #283 (caixa de saída de desenvolvimento) e #120 (chaves do Data Protection no PostgreSQL) foram revisados em
paralelo. Na branch padrão, juntos, o teste `Em_Production_a_rota_responde_404_para_master_e_anonimo_e_o_fake_nao_guarda_mensagem`
pede `/entrar` num host de `Production` cujo banco nunca foi criado. O token antiforgery da página é protegido com as
chaves da tabela `DataProtectionKeys`; sem o esquema, a leitura do anel de chaves falha (`CryptographicException`) e a
página responde 500. Evidência: run de `validate` 45201896758, de 23/11/2026 (PR #100, contra a branch padrão).

É o mesmo caso que o #120 corrigiu em `HospedagemTests`.

## Correção
`tests/Helinho.IntegrationTests/CaixaDeSaidaDevTests.cs`: o teste aplica o `migrate` do pre-deploy (ADR-0002 §7.3)
antes das requisições, com `SeedCommand.RunDatabaseCommandAsync`. Nenhuma asserção mudou; nenhum código de produção mudou.

- `dotnet format --verify-no-changes` e `dotnet build --no-restore -warnaserror` limpos.
