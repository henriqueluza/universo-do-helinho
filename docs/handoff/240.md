## Decisões tomadas sem humano
- **Sucesso em tela própria, não redirecionamento direto para `/entrar`.** O ADR diz "manda para a tela de entrar" e "não faz login automático". A página redireciona para `?definida=True` (o `POST` não fica reenviável), confirma que a senha foi gravada e oferece "Entrar no painel". Motivo: a mesma página serve ao responsável do aluno, que não entra no painel. Alternativa descartada: `/entrar` sem nenhuma confirmação.
- **Link inválido responde 200**, com o mesmo corpo para qualquer causa. Alternativa descartada: 400/404, que não acrescentam nada a quem abre um e-mail.
- **`POST` com campo inválido confere o link antes de mostrar o erro:** link que já não vale leva ao estado de link inválido, não a um formulário que nunca vai funcionar.
- **Limite por IP fixo em código** (10 em 15 minutos, §11.3), sem variável de ambiente: o ADR §13 não prevê variável para ele.
- **Senha com teto de 128 caracteres** no formulário, para limitar o trabalho do hash. A política do Identity não muda (D14).
- **O `painel.js` só reescreve o endereço que traz `token=`.** Sem isso, a tela de sucesso (`?definida=True`) perderia a query e, recarregada, mostraria "link inválido".
- **Fixture de host compartilhada com a #239** (`DefinirSenhaLinkTests.Host`), para os dois arquivos de teste não repetirem o mesmo código e o PR caber em 400 linhas.
- **`docs-writer`, `qa-tester` e os pipelines `insecure-defaults`/`static-analysis` completos não foram chamados:** máquina sobrecarregada, uma execução de testes por vez. Rodei as classes tocadas e o `security-scan.sh`.
