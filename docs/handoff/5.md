# Handoff — Issue #5 (painel: layout base e Identity mínima)

## Estado
Entregue em duas partes (a Issue passou de 800 linhas: 940).

**Parte 1 (este PR):** Identity + cookie (`HttpOnly`, `SameSite=Lax`, antiforgery), políticas `Panel` e `MasterOnly`, `/entrar`, `/sair`, `/acesso-negado`, `ICurrentUser` por claims (papel e `unit_id`), tema `wwwroot/css/theme.css` (tokens do DESIGN.md), Bootstrap 5.3.3 e DM Sans autohospedados, helper de teste `CreateClientAs(papel, unidade, nome)`, `_Layout` simples e páginas `Dashboard` e `Alunos` mínimas.

**Parte 2 (sub-Issue):** menu lateral com todos os itens (Unidades e Administradores só Master), bloco do usuário (nome, papel, unidade, Sair), barra móvel, páginas `Index` das demais seções, convenções `AuthorizeFolder` de Unidades/Administradores e os testes de menu. O código completo está no branch local `issue-5-wip-completo` (referência; não publicado).

## Decisões
- `AddIdentity` fica na Web, mas os stores via `AddAppIdentityStores()` na Infrastructure (a Web não pode citar `AppDbContext`: regra NetArchTest).
- Login recusa quem não é Master/Admin com a mesma mensagem de senha errada (não revela contas); bloqueio após 5 tentativas.
- Autenticação de teste por cabeçalhos (`TestAuthHandler`); desafio/acesso negado seguem no cookie real.
- Bootstrap e fontes baixados dos pacotes npm oficiais (bootstrap@5.3.3, @fontsource/dm-sans@5.1.0) e copiados; sem CDN e sem pacote .NET novo.
