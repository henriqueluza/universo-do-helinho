# Handoff #109 — `terraform test` das validações do Terraform da Railway

**Estado:** pronto. `infra/railway/tests/validacoes.tftest.hcl` versionado; `terraform test` passa com 7 casos. PR empilhado sobre `issue-99-terraform-esqueleto` (PR #100), que já contém os recursos da #107.

## O que o arquivo cobre

Todos os `run` usam `command = plan` com `mock_provider "railway"` e `mock_provider "random"`: o plano é feito em memória, sem token, sem estado e sem chamada à Railway.

| Caso | O que prova |
|---|---|
| `padrao_cria_so_homologacao` | O padrão cria só `homologacao`, e o serviço web recebe exatamente as 13 variáveis esperadas (nenhuma vazia) |
| `producao_ligada_sem_seed` | Com `producao` no mapa o plano fecha; produção não recebe `Seed__Enabled` nem `HELINHO_SEED_PASSWORD`; segredo com valor é enviado |
| `recusa_seed_em_producao` | `seed_enabled` fora de `homologacao` falha em `var.ambientes` |
| `recusa_ambiente_desconhecido` | Nome de ambiente fora da lista falha em `var.ambientes` |
| `recusa_seed_sem_senha` | Seed ligado sem `seed_password` falha |
| `recusa_senha_fraca` | Senha curta e sem as quatro classes falha |
| `recusa_provedor_real_sem_chave` | `Email__Provider = "Brevo"` e `Ai__Provider` real sem chave falham |

## Verificação

- `terraform fmt -check -recursive`, `init -backend=false -lockfile=readonly`, `validate`: limpos (Terraform 1.16.0).
- `tflint` 0.66.0 em contêiner, com `--recursive`: limpo.
- `terraform test`: 7 passed, 0 failed.
- Mutação manual, para confirmar que o teste enxerga a validação: trocando a condição de `ai_api_key` por uma sempre verdadeira, `recusa_provedor_real_sem_chave` falha com "Missing expected failure". A mutação foi desfeita.
- Nenhum `terraform plan`, `apply` ou `destroy`; nenhum token definido. O GitHub Actions estava fora por limite de uso: nenhum check de CI rodou.

## Decisões tomadas sem humano

- Os valores das variáveis não são conferidos nos testes: o provider marca todos como sensíveis, e o módulo só expõe os nomes (`ambientes.<nome>.variaveis_web`).
- O `watch_patterns` do `auto_deploy` não tem caso próprio: é um recurso interno do módulo, e testá-lo exigiria um `run` com `module {}` repetindo as 14 entradas do módulo.
