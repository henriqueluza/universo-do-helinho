## Como as camadas convivem (para os próximos PRs)
Ordem: `bootstrap, legado, tokens, base, components, screens, motion`. Camada posterior vence a anterior, qualquer que seja a especificidade; CSS sem camada vence todas.

1. **Nada novo fora de `@layer`.** Regra fora de camada passa por cima do Recreio inteiro.
2. **Bootstrap** entra por `@import url("../lib/bootstrap/bootstrap.min.css") layer(bootstrap)` (o `<link>` saiu de `_Layout` e `_Bare`; o JS do Bootstrap continua). Fica abaixo de tudo: `.btn`, `.table`, `.nav`, `.alert` do Recreio vencem os do Bootstrap sem `!important`. Telas não portadas seguem usando as classes do Bootstrap com as variáveis `--bs-*` do legado.
3. **`legado`** é o `theme.css` antigo sem alteração, abaixo de `tokens`. Consequência: `--rule`, `--control` e `--fs-title` do Recreio substituem os homônimos do legado; `body`, `h1`, `h2`, `p` e `:focus-visible` seguem a `base` do Recreio.
4. **Ponte:** como `base` zera margem de `h1/h2/p`, o bloco "PONTE do legado" (em `@layer components`, 3 regras) devolve o espaço de `.page-title`, `.section-title` e `.auth-card .page-title`. Remover junto com o legado.
5. **Ao portar uma tela:** escreva o componente em `components`/`screens`; ele já vence o Bootstrap e o legado. Quando nada mais usar uma regra do legado, apague-a; a última remoção apaga `@layer legado`, a ponte, a declaração `@layer bootstrap, legado;` e (se nenhuma tela usar Bootstrap CSS) o `@import`.
6. **`!important` em camada inverte a precedência:** `!important` de camada anterior vence o de camada posterior. Os `!important` do Bootstrap (utilitários `.d-*`, `.visually-hidden`, etc.) vencem os da preview (`[hidden]`, `.only-dark/.only-light`, `.pin-wrap.on`, `html.vt-theme *`, view-transition). Na prática só importa se um elemento combinar um utilitário do Bootstrap com essas classes; evite.
7. `@import` custa uma requisição em série e não leva `asp-append-version`; o Bootstrap quase não muda. Se isso incomodar, trocar por cópia do CSS na camada na limpeza.
8. O CSS da sidebar (`.sidebar`, `.nav-list`, `.nav-item-link`, `.topbar`, `.user-block`) **não existia** no tema antigo: o menu já era sem estilo antes deste PR. A casca (PR 2) cria isso.

- Sem GSAP/Lenis nem CDN: o movimento segue o CSS/WAAPI da preview.

- Tokens `--ai` (de `telas.css`) e `--data*` e `.only-dark/.only-light` entraram agora por serem `tokens`/`base`.
- Ponte de legado em `components` em vez de nova camada, para manter a declaração literal de camadas.
