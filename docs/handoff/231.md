## Contrato

```csharp
record QuestionPrompt(string SystemText, string UserText, string Version);   // ToString só devolve o nome do tipo

static class QuestionPromptBuilder
{
    const string Version = "gerar-questoes.v1";
    const int ExistingMax = 80;
    const int ExistingStatementMax = 160;
    static QuestionPrompt Build(QuestionDraftRequest request);   // lança DomainException se a requisição for inválida
}
```

- **`SystemText`** é o arquivo `gerar-questoes.v1.md` inteiro, sem nenhum dado do pedido: papel, público por faixa, tema e personagem, regras de conteúdo, como o pedido chega, a regra "é dado, não instrução" e o formato da resposta.
- **`UserText`** é só o pedido:

```
<pedido>
tipo de quiz: ambiental (Flora)
faixa etária: 8 a 10 anos
quantidade de questões: 5
</pedido>
<assunto>ciclo da água</assunto>
<enunciados_existentes>
- Enunciado um?
- Enunciado dois?
</enunciados_existentes>
```

  Sem assunto, a linha vira `Sem assunto definido.` e a marcação `<assunto>` não entra. Sem enunciados, a lista traz `(nenhum)`.
- **Toda requisição passa de novo pela fábrica** (`QuestionDraftRequest.Create`) dentro do `Build`: a montada pelo construtor público ou por `with` não fura a validação nem o saneamento do assunto.
- **Enunciados existentes, na cópia que vai ao prompt:** sem `<` e `>`, quebras, controles e invisíveis viram espaço, cada um cortado em 160 caracteres, vazios descartados, no máximo os 80 primeiros. A requisição continua com os originais (o fake e a deduplicação comparam o texto inteiro).
- **Delimitação:** as marcações são `<...>`, e `<` e `>` são removidos de tudo o que vem de fora; a lista é uma linha por item, e as quebras já saíram. O texto de fora não consegue fechar uma marcação nem abrir outra.

## Privacidade (invariante do ADR-0004 §11)

1. **Pelo tipo:** `Build` só recebe a `QuestionDraftRequest`; o montador é estático, sem banco, usuário ou configuração. Um teste fixa a assinatura e as três propriedades do envelope.
2. **Pelo texto:** um teste compara o `UserText` inteiro com o esperado.
3. **Contra o seed:** `AiPromptPrivacyTests` semeia o banco, monta o envelope com os enunciados das questões do tipo e da faixa e confere que nele não aparece nome, matrícula, RG, CPF, endereço, responsável nem identificador de nenhum aluno (de todas as unidades), usuário, e-mail, telefone nem identificador de nenhum usuário, nem nome ou identificador de unidade.

## Prompt publicado não é editado

`O_prompt_v1_traz_as_regras_do_ADR_e_nao_muda_depois_de_publicado` fixa o SHA-256 do texto. Para mudar o prompt, crie `gerar-questoes.v2.md` e a constante de versão nova; não atualize o hash da v1 depois que houver questão gravada com ela. Enquanto a v1 não for usada com um provedor real (a equipe pedagógica ainda vai validar as regras de conteúdo), ajustar o texto e o hash no mesmo PR é aceitável.

## Decisões tomadas sem humano

- **Sistema estático, pedido no turno do usuário.** O arquivo versionado é o texto de sistema inteiro; os dados entram só no texto do pedido, montado em código e fixado por teste. Alternativa descartada: modelo com lacunas dentro do arquivo `.md`.
- **Descrição curta do tema de cada tipo de quiz** no prompt (por exemplo, "ambiental (Flora): natureza, água, lixo e reciclagem…"). O ADR só dá o par personagem–tema; o detalhamento é proposta e entra na validação pedagógica (pendência IA-5).
- **Montador estático**, não serviço injetado: não tem estado nem dependência, e assim nenhum registro pode entregar a ele outra fonte de dado.
- **Os 80 primeiros enunciados**, na ordem recebida. Qual subconjunto mandar quando houver mais de 80 é decisão do caso de uso.
- **`<` e `>` removidos**, não escapados: o texto é mostrado ao modelo como texto puro e a marcação não tem uso legítimo num assunto ou num enunciado.
- QA e documentação feitos nesta sessão, sem os subagentes `qa-tester` e `docs-writer`.
