# Handoff #33 — GET e POST /user/inventory

**Estado:** implementado e testado (`UserInventoryTests`, 118 testes verdes).

**Decisões**
- Caso de uso em `Helinho.Application/Profile/UserInventory.cs`; endpoints em `UserEndpoints.cs`. Sem migração, DTO novo ou pacote.
- POST substitui a seleção inteira (remove + insere num único `SaveChanges`) e responde com a seleção gravada (P10), ordenada por `type`.
- Tipos aceitos (catálogo fixo no jogo, P12): `cabelo`, `pele`, `roupa`, `rosto`, `acessorio`. Um item por tipo, no máx. 5 itens, `id` ≤ 60 e `name` ≤ 120 caracteres. Violação → 400 `invalid_inventory` (PROPOSTA registrada em P4). Aluno inexistente → 403; sem token → 401.
- O aluno é sempre o do token, então não há como alterar o inventário de outro.

**Próximo passo:** aceite da contratante para o código `invalid_inventory` e para os nomes dos tipos.

**Pendente:** corrida entre dois POSTs simultâneos do mesmo aluno pode violar o índice único (500); fora do escopo, tratar se aparecer.
