# Handoff #16 — Cadastro e edição de aluno

**Estado:** implementado. `Pages/Alunos/Novo` e `Editar/{id}` (modelo próprio `StudentInput`), caso de uso `SaveStudent` (Application), `Cpf` (Domain), porta `IStudentAccounts` + `StudentAccounts` (Infrastructure). Botão "Novo aluno" e link "Editar" na listagem (só Admin).

**Decisões**
- Só o papel Admin cadastra/edita (política `AdminOnly`); a unidade vem do `ICurrentUser`, nunca do formulário. Aluno de outra unidade não passa pelo filtro global: 404.
- O cadastro cria um usuário Identity sem senha (papel Student) na mesma transação do aluno; credenciais ficam para outra Issue (fora de escopo). Matrícula gerada (`ALU-` + 10 hex).
- Mensagens de validação são fixas e nunca ecoam CPF/RG; nada de CPF/RG em log. CPF gravado no formato 000.000.000-00.
- Método novo `Student.UpdateRegistration`/`SetGuardianApproval`: sem mudança de esquema, sem migração, DTO ou pacote.
