## Contrato que a UI vai consumir

```csharp
// Helinho.Application.Ai — registrado como Scoped em Composition/Areas/Ia.cs
public sealed class GetAiDraftJob
{
    Task<GetAiDraftJobResult> HandleAsync(Guid jobId, CancellationToken ct);
}

public sealed record GetAiDraftJobResult(GetAiDraftJobStatus Status, AiDraftJobView? Job = null);
public enum GetAiDraftJobStatus { Found, NotFound, Disabled, Forbidden }

public sealed record AiDraftJobView(
    Guid Id, QuizType QuizType, AgeBand AgeBand, int RequestedCount, string? Subject, AiJobStatus Status, string? FailureReason,
    int GeneratedCount, int ValidCount, int InvalidCount, int DuplicateCount, DateTimeOffset CreatedAt, DateTimeOffset? FinishedAt,
    IReadOnlyList<AiDraftView> Drafts) { int ReviewedCount { get; } }

public sealed record AiDraftView(
    Guid Id, int Position, string Statement, IReadOnlyList<string> Options, int CorrectIndex, string Explanation,
    AiSuggestionStatus Status, Guid? QuestionId);
```

- Serve à página `GET /questoes/ia/{jobId}` e ao *polling* `?handler=Status` (que usa só `Status` e os contadores).
- Estados para a tela: `Pending` (na fila), `Processing` (gerando), `Succeeded` (cartões; `Drafts` vazio = estado vazio, com `InvalidCount` e `DuplicateCount` como motivo), `Failed` (`FailureReason` é código de `AiFailureCodes`: `ai_timeout`, `ai_unavailable`, `ai_rate_limited`, `ai_refused`, `ai_invalid_output`, `ai_misconfigured`, `ai_disabled`, `ai_job_missing`, `expired`, `max_attempts`).
- `NotFound` também para pedido avulso (`Single`): ele não tem tela de revisão. `Disabled` → 404 na borda.
- **`Statement`, `Options`, `Explanation` e `Subject` são texto não confiável** (gerado por IA ou digitado): exibir só pela codificação padrão do Razor, nunca com `Html.Raw`.

## Decisões tomadas sem humano

- **Vencido = criado há mais de 10 minutos + `Ai:TimeoutSeconds`** (11 min 30 s no padrão), não os 10 minutos secos do ADR. A fila não começa um trabalho depois da validade de 10 minutos, mas um tratador que começou no último segundo ainda pode concluir até o prazo da chamada. Com 10 minutos secos, a tela poderia mostrar "falhou" e, segundos depois, as sugestões. Ver "Onde o ADR não bastou".
- **A conferência é um `UPDATE` condicional** (`ExecuteUpdateAsync` com o estado não concluído e a data no `WHERE`), feito a cada leitura do pedido. Não carrega a entidade nem usa exceção de concorrência: se o trabalhador concluiu antes, a condição não casa e nada muda. Quando nada casa, não há escrita.
- **Se o trabalhador concluir depois da conferência** (só possível se a gravação final dele demorar além do prazo), a conclusão dele vence: o pedido passa de `Failed` (`expired`) a `Succeeded` com as sugestões. É a ordem escolhida na #257 (o `Status` do pedido não é token de concorrência), para não derrubar a gravação única do processador.
- **Qualquer administrador lê qualquer pedido**: as sugestões são globais, como o banco de questões (ADR-0004 §9.3). O identificador é um GUID.
- QA e documentação feitos nesta sessão, sem os subagentes `qa-tester` e `docs-writer`.

## Onde o ADR não bastou

- O ADR (§10.2) diz "não concluído há mais de 10 minutos". Não considera o tratador que ainda está dentro do prazo da chamada. Implementado com a folga do prazo; se o Henrique preferir os 10 minutos secos, é trocar uma linha em `GetAiDraftJob`.
